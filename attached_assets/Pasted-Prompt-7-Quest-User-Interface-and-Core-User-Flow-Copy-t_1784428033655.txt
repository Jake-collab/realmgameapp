# Primary Objective
Implement the core Quest user journey:
```text
Quest Home
    ↓
Quest Summary or Quest List
    ↓
Quest Detail
    ↓
Start Quest
    ↓
Active Quest
    ↓
Complete Objectives
    ↓
Submit Required Proof
    ↓
Completion or Review Status

The finished Quest experience should feel:

* Focused
* Encouraging
* Activity-oriented
* Modern
* Minimal
* Game-like without appearing childish
* Consistent with the blue-and-green Worlds design direction

The active Quest must remain the most visually important part of Quest Home.

6. Home State When No Quest Is Active

When the user has no active Quest:

* Show the current prioritized Daily Quest as the dominant experience.
* Include title, brief objective, points, estimated time, and difficulty.
* Use one primary action:
    * View Quest
    * Or Start Quest only if sufficient details are already displayed and the user can make an informed decision

Prefer opening Quest Detail before initiation when safety, location, proof, or accessibility information is important.

Do not show an empty dashboard merely because no Quest is active.

17. Start Quest Interaction

When the user taps Start Quest:

1. Prevent repeated taps.
2. Show a brief loading state.
3. Call the Prompt 6 startQuest operation.
4. Handle an existing participation idempotently.
5. Route to Active Quest on success.
6. Update Home, Quests, Detail, and participation queries.
7. Show a safe error if availability changed.
8. Do not award points.
9. Do not optimistically pretend the Quest started before the trusted operation succeeds.

For Quests involving meaningful safety, travel, permissions, or proof requirements, show a concise pre-start confirmation.

The confirmation may summarize:

* Expected duration
* Location requirement
* Proof requirement
* Deadline
* Safety notice

Avoid unnecessary confirmation for trivial low-risk Quests.

25. Proof Submission Flow

2. Allow the user to provide required evidence.
