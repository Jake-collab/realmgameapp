# Primary Objective
Implement a complete, secure, production-ready authentication and onboarding system for Worlds.
The finished flow should support:
```text
Native Splash
    ↓
Session Check
    ↓
Unauthenticated Welcome Screen
    ↓
Sign Up or Log In
    ↓
Email Verification When Required
    ↓
First-Time Onboarding
    ↓
Main Worlds Application

Returning authenticated users who have completed onboarding should bypass the welcome and onboarding screens and enter the main application.

Do not rely only on the client-side availability check.

10. Account Creation Flow

Implement the sign-up transaction carefully.

Expected sequence:

1. Validate the form.
2. Confirm Supabase is configured.
3. Check normalized username.
4. Call Supabase Auth sign-up.
5. Allow the database trigger or secure backend function to create the base profile.
6. Update allowed profile fields such as username and display name.
7. Record onboarding state as not started or in progress.
8. Route to email verification if required.
9. Otherwise route to onboarding.
10. Show clear success or recoverable failure states.

Do not insert privileged fields from the client.

The user must never choose:

* Role
* Account status
* Moderation state
* Administrative permissions

Default role must remain user.

⸻

11. Partial Sign-Up Failure Handling

Account creation can partially succeed.

Handle cases such as:

* Auth user created but profile update failed
* Profile exists but username assignment failed
* Network disconnect after Auth success
* Email confirmation required
* Duplicate username
* Duplicate email
* Rate limit
* Password policy rejection

Create recovery behavior.

For example:

* On the next session load, detect a missing or incomplete profile.
* Route the user to a profile-completion screen or resume sign-up state.
* Do not create a second Auth user.
* Do not strand the user permanently.
* Do not expose raw database errors.

Document the recovery strategy.

Rules:

Unauthenticated user

* Welcome
* Login
* Sign Up

* Reset Password callback routes

Must not access:

* Main Quest routes
* Main Hunt routes
* Profile
* Settings
* Notifications
* Protected onboarding data

Authenticated but unverified user

May access:

* Verification flow
* Logout

Authenticated and verified but onboarding incomplete

May access:

* Onboarding routes
* Logout

Authenticated and onboarding complete

* Main Worlds app
* Shared Profile
