13. Quest Initiation

Implement a secure startQuest domain operation.

Expected behavior:

1. Confirm authenticated user.
2. Confirm active account.
3. Load the Quest.
4. Evaluate availability and eligibility.
5. Check for an existing active participation.
6. Check repeatability and prior completion.
7. Create the participation record.
8. Set started_at.
9. Set an expiration time if applicable.

Requirements:

* Use an RPC, Edge Function-ready service, or safe transactional database function where needed.
* Do not award points at start.
* Do not allow a user to start a draft or expired Quest.

20. Automatic Completion Versus Manual Review

→ Completion transaction

21. Quest Completion Transaction

Implement one authoritative completeQuest operation.

It must:

1. Confirm authenticated user.
2. Confirm participation ownership.
3. Confirm valid participation state.
4. Confirm all required objectives are satisfied.
5. Confirm proof approval where required.
6. Confirm the Quest is not already completed.
7. Confirm the reward has not already been issued.
8. Set participation to completed.
9. Set completed_at.
10. Record the exact awarded point amount.
11. Insert a points-ledger transaction.
12. Use a unique idempotency key.
13. Return the completion result.

The completion update and points-ledger insert must occur atomically.

If point insertion fails, participation must not remain completed without a recoverable award state.

Prefer a secure database function or trusted server-side transaction.

Do not trust a point value sent from the client.

Load the reward from the authoritative Quest record or a versioned participation snapshot.
