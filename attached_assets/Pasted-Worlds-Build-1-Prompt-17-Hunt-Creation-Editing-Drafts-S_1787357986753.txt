The application is named:

Worlds

Prompts 11–14 completed the Hunt domain, map/discovery, joining, invitations, active gameplay, proof, completion, Progress, and leaderboards.

Prompt 16 added public profiles, friends, social privacy, blocking, and safe friend-based Hunt invitation eligibility.

This prompt must implement the complete user-facing Custom Hunt creation and creator-management system.

Do not rebuild Hunt gameplay logic.

Do not duplicate the map, media, proof, moderation, social, notification, points, or authentication systems.

Do not add payments, creator payouts, subscriptions, ticketing, paid Hunts, paid hints, or monetization.

Do not allow user-created Hunts to bypass moderation.

Do not redesign the approved navigation.

⸻

Primary Objective

Implement a guided creator flow allowing an eligible Worlds user to:

1. Start a Custom Hunt draft.
2. Enter Hunt details.
3. Choose privacy and participation settings.
4. Configure scheduling.
5. Choose a public starting area.
6. Add Hunt stops.
7. Add clues.
8. Add location requirements where appropriate.
9. Add proof requirements.
10. Configure ordered or unordered progression.
11. Add accessibility and safety notes.
12. Invite friends where appropriate.
13. Preview the Hunt exactly as players will see it.
14. Validate the draft.
15. Submit it for moderation.
16. View moderation status.
17. Make requested changes.
18. Publish when approved and eligible.
19. Manage future occurrences.
20. Cancel or archive appropriately.
21. View creator-owned Hunt status.
22. Preserve draft data safely.

The experience should feel:

* Simple
* Guided
* Creative
* Map-oriented
* Safe
* Mobile-first
* Not like a giant admin form
* Easy enough for a normal user to create a Hunt without understanding the backend

4. Draft Creation

When a user taps + Create:

1. Verify authentication.
2. Verify account is eligible to create Custom Hunts.
3. Create one draft record transactionally.
4. Set owner to the authenticated user.
5. Set type to custom.
6. Set status to draft.
7. Store a creation-version identifier.
8. Route into Basic Details.
9. Return the existing newest incomplete draft only if product policy explicitly allows resume behavior.
10. Do not create multiple empty drafts from rapid repeated taps.

The client must not set:

* Admin approval
* Published status
* Moderation approval
* Platform ownership
* Creator verification status

* Details edited
* Privacy changed
