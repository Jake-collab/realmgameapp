# Primary Objective
Implement a secure, consent-based social foundation that allows users to:
1. View privacy-safe public profiles.
2. Search for eligible users.
3. Send friend requests.
4. Accept or decline friend requests.
5. Cancel outgoing requests.
6. Remove friends.
7. Block users.
8. Unblock users.
9. Report users through the shared report system.
10. Control who can discover, request, invite, and view them.
11. View approved public achievements, titles, badges, and statistics.
12. Invite eligible friends to Hunts through the existing trusted Hunt invitation operation.
13. Preserve privacy and safety across Quest, Hunt, Progress, leaderboards, and notifications.
The experience should feel:
- Modern
- Minimal
- Safe
- Private by default
- Consent-based
- Social without becoming feed-driven
- Suitable for adults and general audiences
- Consistent with the Worlds visual system

25. Send Friend Request

Implement a trusted sendFriendRequest operation.

It must:

1. Authenticate the requester.
2. Verify both accounts are active.
3. Prevent self-request.
4. Check target discoverability and request permission.
5. Check blocks in both directions.
6. Check existing friendship.
7. Check existing outgoing request.
8. Check existing incoming request.
9. Resolve reverse-request behavior safely.
10. Apply rate limits and abuse controls.
11. Create one pending request.
12. Emit a notification-ready event.
13. Return authoritative relationship state.

Recommended reverse-request behavior:

* When A requests B while B already has a valid pending request to A, accept the existing request transactionally if product policy permits.
* Otherwise return Incoming Request and require explicit acceptance.

Choose and document one behavior.

Do not allow the client to create friendship rows directly.
